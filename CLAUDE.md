# CLAUDE.md — context for working in this repository

Read this first in a new session. It says what the repo is, where the data
live, how to run things, which conventions are non-obvious, and where work
was left off.

## What this repository is

Analysis code for the total solar eclipse of 8 April 2024 observed from
Dallas, TX (Singh, Sharma, Arora, Burman, Gandhi):

* **`Paper-I-Analysis/`** — *Linear Polarimetry of the Solar Corona during the
  TSE of 8 April 2024: Multi-Band Observations and HDR Imaging* (Solar Physics,
  under review). Complete, validated, self-contained: config + utils + 12
  numbered notebooks that regenerate every table and figure from the calibrated
  frames. **Everything a session needs to know about it is in
  `Paper-I-Analysis/README.md` and `Paper-I-Analysis/docs/`.**
* Paper II (polarised brightness, electron density) is **not** in this repo
  yet; its prototype lives on the data SSD in `Paper-II-Analysis/tests_Claude/`
  (`config.py`, `pipeline_utils.py`, notebooks 01–08). Migrating it here is the
  obvious next project; it should copy helpers, not import across folders.

Owner: Paras Sharma (Stony Brook), GitHub `timedilatesme`. Co-authors: Suprit
Singh (IIT Delhi, PI), Bharti Arora, Shivam Burman, Chaitanya Gandhi.

## Data and environment

* **Large data are not in git.** The calibrated frames (145 × 545 MB) and the
  legacy products live on an external SSD; `Paper-I-Analysis/config.py`
  resolves the data root from `$SOLAR_ECLIPSE_DATA_ROOT`, else
  `Paper-I-Analysis/local_paths.toml` (git-ignored; see
  `local_paths.example.toml`), else `/Volumes/WD_SSD/Solar Eclipse 2024 Data`.
  Regenerated products (`Paper-I-Analysis/products/`, ~7 GB) and full-size
  figures (`Paper-I-Analysis/figures/`) are git-ignored; small copies of the
  figures for the READMEs are committed in `Paper-I-Analysis/docs/img/`.
* **Python env:** `~/.venvs/solar-corona` (uv, Python 3.12, packages from
  `Paper-I-Analysis/requirements.txt`). It lives *outside* the SSD because the
  SSD is exFAT and `uv pip install` fails on it. Recreate with
  `uv venv --python 3.12 ~/.venvs/solar-corona && uv pip install --python ~/.venvs/solar-corona/bin/python -r Paper-I-Analysis/requirements.txt`.
* **exFAT quirk:** macOS creates `._*` AppleDouble files on the SSD, including
  inside `.git/`, which makes git print `error: non-monotonic index`. Fix with
  `dot_clean -m .` in the repo root. `._*` is git-ignored.
* Network is needed once for `data/de421.bsp` (Skyfield downloads it) and once
  for `data/reference_stars.csv` (Simbad); both are cached afterwards.

## Running Paper I

```bash
cd Paper-I-Analysis
./run_all.sh              # all notebooks in order (~2.5 h; notebook 02 alone is ~75 min)
./run_all.sh 05 06 07 08  # a subset
```

Executed copies with outputs go to `products/executed/`; the notebooks in
`notebooks/` are committed without outputs. Notebooks are generated from a
builder script kept in the session scratchpad (not in the repo) — editing the
`.ipynb` files directly is fine.

## Conventions that are easy to get wrong

* Array coordinates: x = column (right), y = row (down). Celestial North is
  α = 168° CCW from +x *as displayed in camera orientation*; unit vectors
  `n = (cos α, −sin α)`, `e = (−sin α, −cos α)`; a sky offset (sep, PA east of
  north) → `sep·(sin PA·e + cos PA·n)` px. `utils.north_east_vectors`,
  `utils.sky_offset_to_pixels`. Verified against the star field (notebook 03).
* Polariser positions: pol1 = 0°, pol2 = +60°, pol3 = −60° w.r.t. the sensor x
  axis; Position 4 = no polariser (excluded). Plane order in every 3-plane FITS
  is pol1, pol2, pol3.
* Camera clock was on IST; FITS `DATE-OBS` is converted to UTC in `utils.fits_timestamp_utc`.
* Sun centre of every stacked/HDR product = array centre (4128, 2752).
* `config.SUN_CENTER_ROTATION`: `"astrometric"` (default, correct) or
  `"legacy"` (reproduces the submitted figures, needs the by-eye channel shifts).
* `config.MOON_CENTERS_SOURCE`: `"legacy"` (the 2024 CHT table, default) or `"recomputed"`.
* Stacking is a **mean**; the stacks contain **124** frames
  (`config.EXTRA_EXCLUDED_FRAMES`), not the 130 the manuscript says.

## State of validation (see `Paper-I-Analysis/docs/PROVENANCE.md`)

Legacy mode reproduces the paper's stacks at corr ≥ 0.9997, HDR ≥ 0.99995,
figures ≥ 0.998. Astrometric mode re-registers the polariser channels by a few
px (the by-eye shifts become unnecessary); `notebooks/99` reports the numbers.
